### 1.1 Path Strategy (BINDING)

This API uses **nested paths** for subordinate resources to maintain clear resource hierarchies.

Pattern: `/api/{parent}/{parentId}/{child}`

Examples:
- Projects -> Sources: `/api/projects/:projectId/sources`
- Projects -> Processing Runs: `/api/projects/:projectId/runs`
- Projects -> Datasets: `/api/projects/:projectId/datasets`
- Sources -> Schema Mapping: `/api/sources/:sourceId/schema-mapping`
- Sources -> De-identification Config: `/api/sources/:sourceId/deidentification`

**Exception:** Top-level resources (auth, organizations, projects) use flat paths.

### 1.2 Parameter Naming Convention (BINDING)

All path parameters follow format: `:{resourceName}Id`

Rules:
- Use shortest clear name
- Singular resource name only
- No qualifier prefixes

Examples:
- Project resource -> `:projectId` (not `:dataProjectId`)
- Source resource -> `:sourceId` (not `:dataSourceId`)
- Run resource -> `:runId` (not `:processingRunId`)
- Dataset resource -> `:datasetId` (not `:outputDatasetId`)
- Invitation resource -> `:invitationId` (not `:teamInvitationId`)
- Token parameter -> `:token` (for password reset, invitation accept)

### 1.3 Response Envelope Format (BINDING)

All successful responses use **minimal envelope format**:

```json
{
  "data": {
    // Endpoint-specific response
  }
}
```

Paginated responses use:
```json
{
  "data": [...],
  "pagination": {
    "page": 1,
    "limit": 20,
    "total": 150,
    "totalPages": 8,
    "hasMore": true
  }
}
```

Error responses follow Constitution Section C:
```json
{
  "error": {
    "code": "NOT_FOUND",
    "message": "Project not found"
  }
}
```

## 5. Parameterized Endpoint Failure Modes

All endpoints with :id parameters use parseIntParam validation:

| Input Type | Example | Status | Code |
|------------|---------|--------|------|
| Valid | /projects/123 | 2xx | - |
| Non-numeric | /projects/abc | 400 | INVALID_ID |
| Negative | /projects/-5 | 400 | INVALID_ID |
| Zero | /projects/0 | 400 | INVALID_ID |
| Float | /projects/1.5 | 400 | INVALID_ID |
| Not found | /projects/999999 | 404 | NOT_FOUND |

Token parameters (`:token`) validate format but don't use parseIntParam:
| Input Type | Example | Status | Code |
|------------|---------|--------|------|

### Multi-Tenant Middleware Pattern

```typescript
// All org-scoped routes
async function requireOrgAccess(req, res, next) {
  const { organisationId } = req.params;
  if (req.user.organisationId !== parseInt(organisationId)) {
    return sendError(res, 403, 'FORBIDDEN', 'Access denied');
  }
  next();
}

// All project-scoped routes
async function requireProjectAccess(req, res, next) {
  const project = await findProjectById(req.params.projectId);
  if (!project || project.organisationId !== req.user.organisationId) {
    return sendError(res, 404, 'NOT_FOUND', 'Project not found');
  }
  req.project = project;
  next();
}
```
